## 源码核对修正了设计文档的两个认知

1. **patch 覆盖是逐字段的，不是整行替换。** `vendor/include/src/index.ts:121-124`：`config` 作为单个键写入时整体替换 config；`disabled` 是独立键，只覆盖 config 不碰 disabled，反之亦然。因此我们的 `tool-web` 覆盖行只需 `disabled: false`（dsh-web-app 的覆盖行也只写了 `disabled: true`，base 的 config 原样保留）。**"searchProvider 与 fetchProvider 必须一起写"的规则仍然成立**——那是因为它们同属 web 行的 config。
2. **patch 里写 `name` 必须与目标行现有 name 一致，否则整个 patch 被跳过**（`vendor/include/src/index.ts:116-119`，只 warn 不抛错）。我们的覆盖行不写 `name`。

其余重要事实（`DeepSeekSearchProvider` 构造参数是 thunk、`credentials.resolve/describe` 是 async、`@deepseek-ai/schemastery` 包名、`resolveModel` 而非 `resolveModelInfo`、peer 依赖的真实版本范围）见 `docs/knowledge-base/dsh-source-verified.md`。
