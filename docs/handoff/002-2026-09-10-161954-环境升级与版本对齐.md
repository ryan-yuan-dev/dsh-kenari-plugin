## 环境变更详情

### dsh 安装方式的改变

| 项 | 变更前 | 变更后 |
|---|---|---|
| 版本 | `0.1.0-rc.6` | `0.1.5-rc.1` |
| 位置 | npx 临时缓存 `~/.npm/_npx/1e7f6d9597241db0/` | 全局 `/opt/homebrew/lib/node_modules/@deepseek-ai/dsh` |

原 npx 缓存方式**不稳固**（缓存可被清理），已由全局安装取代。

`dsh plugin` 的实现是转发给 pnpm。变更前机器上没有 pnpm，导致所有插件安装/验证命令都无法执行。现已安装 `12.3.4` 并实测通过（真实安装了一个包验证）。

Node 26 已移除 corepack，所以用 `npm i -g pnpm` 安装。

## 发现的重要陷阱

### 子包的 npm latest 标签不可信

```
@deepseek-ai/dsh-web-fetch-http
  latest: 0.0.1-rc.5     ← 默认装这个，与 dsh 0.1.5-rc.1 不匹配
  next:   0.1.5-rc.1     ← 与主版本对齐
```

**安装任何 dsh 子包必须显式指定版本**，例如：

```sh
dsh plugin --profile web add @deepseek-ai/dsh-web-fetch-http@0.1.5-rc.1
```

裸包名会装到不对齐的 `latest`。首次操作时已踩此坑并修正。

### `tool-web` 在 web profile 下被禁用

`--dump-config` 显示：

```yaml
# == @deepseek-ai/dsh-base, patched by @deepseek-ai/dsh-web-app
- id: tool-web
  name: '@deepseek-ai/dsh-tool-web'
  config:
    fetch: true
    searchTimeoutMs: 60000
  disabled: true
```

**web 工具在 web profile 下整体不注册。** 这不是 provider 配置问题，需要 patch 显式覆盖 `disabled`。

### 新版默认 web 配置与旧版不同

| 配置项 | `0.0.1-rc.1` | `0.1.5-rc.1` |
|---|---|---|
| `web.fetchProvider` | 不存在 | `http` |
| `web-fetch-http` 行 | 不存在 | 默认挂载 |
| `tool-web.fetch` | `false` | `true` |

即 fetch 已默认启用。设计文档据此调整：Kenari 的 fetch 从"从无到有"改为"替换默认 provider"。

## submodule 引入过程记录

首次尝试失败两次，原因不同，记录供后续参考：

1. `git submodule add --depth 1 -b dsh-v0.1.5-rc.1 ...` → **`-b` 只接受分支名，不接受 tag**，报 `'origin/dsh-v0.1.5-rc.1' is not a commit`
2. 首次尝试还遇到一次 `SSL_ERROR_SYSCALL` 瞬时网络故障（复测正常）

成功方法：先手动克隆再注册。

```sh
mkdir -p vendor
git clone --depth 1 --branch dsh-v0.1.5-rc.1 https://github.com/deepseek-ai/deepseek-harness vendor/deepseek-harness
git submodule add https://github.com/deepseek-ai/deepseek-harness vendor/deepseek-harness
```

`--branch` 接受 tag，`submodule add -b` 不接受。体积约 116M。

### 5 个包的 install scripts 被 npm 拦截

全局安装 dsh 时 npm 报告以下包的 install scripts 未执行：

```
@deepseek-ai/dsh-subprocess-local (postinstall: node scripts/ensure-spawn-helper.mjs)
koffi (install)
node-pty (install, postinstall)
@google/genai (preinstall: no-op)
protobufjs (postinstall)
```

dsh 目前能启动、能 `--dump-config`、能装插件。但 **`dsh-subprocess-local` 的 spawn helper 与 `node-pty` 关系到 bash 工具、PTY 终端、subagent 等能力**，是否受影响未验证。
