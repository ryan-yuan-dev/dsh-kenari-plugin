- 本地安装是 **pnpm link**（profile 的 package.json 里 `dsh-kenari-plugin: link:../../../workspace/opc/dsh-kenari-plugin`）。改源码后只需 `pnpm build`，**不要重新 `dsh plugin add`**

### 3.3 源码核对修正的两个认知（设计文档原文已被推翻）

1. **patch 覆盖是逐字段的**：`config` 作为单键写入时才整体替换 config；`disabled` 是独立键。`tool-web` 重新启用只需 `disabled: false`（web-app 禁用时也只写了 `disabled: true`）。但**同一 config 内的字段仍须写全**（searchProvider 与 fetchProvider 一起写）
2. **patch 行写 `name` 必须与目标行现有 name 一致**，否则整个 patch 被静默跳过（warn 不抛错）。覆盖行一律不写 `name`

证据与更多签名见 `docs/knowledge-base/dsh/dsh-source-verified.md`（源码实读，权威性最高）。

## 4. 下一任务：第 1 期 web fallback（开工包）

### 4.1 任务拆解

1. `src/http.ts` —— Kenari HTTP 客户端（base/超时/重试/错误映射集中于此）
2. `src/errors.ts` —— 状态码与错误信封映射（401/402/403/429 退避等）
3. `src/web/search.ts` —— `POST /v1/web/search`；`max_results = min(req.maxResults ?? 5, 10)`；`results[]` → `WebSearchSource { url, title, snippet: content }`，`content` 留空
4. `src/web/fetch.ts` —— `POST /v1/web/fetch` → `WebFetchResult { url, statusCode: 200, body: {kind:'text', content}, truncated }`，`links[]` 附正文尾部
5. `src/web/fallback.ts` —— 组合 provider（Kenari 优先 → 兜底），含回退日志（方向、失败原因、耗时）

### 4.2 兜底实例的源码事实（关键，别再发现一遍）

- `DeepSeekSearchProvider` 构造参数是 **thunk** `() => DeepSeekSearchProviderOptions`；`available()` 判定 = 有 `apiKey` **或**有 `resolveApiKey`，且 `URL.canParse(baseURL)`。兜底实例必须传 `resolveApiKey`（每次现场解析 `DEEPSEEK_API_KEY`），否则有 key 也判不可用
- `HttpFetchProvider` 构造 `(limits, resolveAddresses?)`，第二参数有默认值，只传 limits 即可；limits 5 字段：maxResponseBytes / maxBodyChars / timeoutMs / maxRedirects / userAgent
- 两个类从包入口 import：`@deepseek-ai/dsh-web-search-deepseek`、`@deepseek-ai/dsh-web-fetch-http`（peer 已定版）。**只实例化，绝不 `register*Provider`**（id 冲突抛 `WEB_DUPLICATE_PROVIDER`，插件加载失败）
- 官方 key 读取模式（照抄 web-search-deepseek 的实现）：`ctx.get('credentials')` 优先，seam 缺失时回退 `launchEnvironmentOf(ctx)`；`credentials.resolve/describe` 都是 **async**
- schemastery API 形状：`z.string().role('credential-ref').default(...)`、`z.number().step(1).min(n).default(...)`、`z.boolean().default(...)`

### 4.3 验证标准

1. patch 生效后 `tool-web` 的 `disabled` 为 `false`，`web_search`/`web_fetch` 工具注册可见（**已达成**，第 0 期完成）
2. 不配 `DEEPSEEK_API_KEY` → `web_search` 走 Kenari
3. 配了 `DEEPSEEK_API_KEY` → 仍走 Kenari（Kenari 优先）
4. Kenari key 无效 → 回退到官方，日志有记录
5. `fallbackEnabled: false` → 退回 dsh 默认
