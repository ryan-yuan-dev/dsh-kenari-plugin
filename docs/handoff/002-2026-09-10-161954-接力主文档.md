## 第 1 期：web fallback

**写 4 个文件**：`src/http.ts`（Kenari HTTP 客户端：超时/重试/错误映射集中处）、`src/errors.ts`（状态码映射）、`src/web/search.ts`、`src/web/fetch.ts`、`src/web/fallback.ts`（组合 provider + 回退日志：方向/原因/耗时）。

**映射要点**：

- search：`max_results = min(req.maxResults ?? 5, 10)`；`results[]` → `WebSearchSource{url, title, snippet: content}`，顶层 `content` 留空
- fetch：→ `{url, statusCode: 200, body:{kind:'text', content}, truncated}`；`links[]` 附正文尾部

**兜底实例（写代码前先记死）**：

- `DeepSeekSearchProvider` 构造参数是 **thunk** `() => options`；`available()` = 有 apiKey 或有 `resolveApiKey`，且 `URL.canParse(baseURL)` → 兜底实例必须传 `resolveApiKey`（每次现场解析），否则有 key 也判不可用
- `HttpFetchProvider(limits, resolveAddresses?)` 第二参有默认，只传 limits；5 字段：maxResponseBytes/maxBodyChars/timeoutMs/maxRedirects/userAgent
- 两者 import 自包入口，**只实例化不注册**
- key 读取照抄官方：`ctx.get('credentials')` 优先，缺 seam 回退 `launchEnvironmentOf(ctx)`；`resolve`/`describe` 都是 **async**

**验证**：① dump-config 已通过；② 无 `DEEPSEEK_API_KEY` → 走 Kenari；③ 配了 → 仍走 Kenari；④ Kenari key 无效 → 回退官方且有日志；⑤ `fallbackEnabled: false` → 退回默认。

**计费纪律**：`web_search`/`web_fetch` 按次扣真实余额，测试最小调用量。**`KENARI_API_KEY` 尚未配置**（验证 ②③④ 前需用户配）；`DEEPSEEK_API_KEY` 是否已配置未核实。
