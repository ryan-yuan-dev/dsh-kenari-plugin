### 已解除的未知项

**`@deepseek-ai/dsh-web-fetch-http` 是否导出可实例化的 provider 类** —— 已验证：**是**。

导出 `HttpFetchProvider` 类与 `LOCAL_FETCH_PROVIDER_ID` 常量（值为 `http`）。`0.1.5-rc.1` 的 `HttpFetchLimits` 为 5 个字段（`maxResponseBytes`、`maxBodyChars`、`timeoutMs`、`maxRedirects`、`userAgent`），旧版 `0.0.1-rc.5` 多一个 `maxUrlLength`。`available()` 恒为 `true`（匿名公开抓取，无凭据可查）。

所以 fetch 兜底可实现：直接实例化 `HttpFetchProvider`，**不注册**（避免与 `dsh-base` 已注册的 id 冲突），只持有实例调用其 `fetch()`。

同类验证结果：`dsh-web-search-deepseek` 导出 `DeepSeekSearchProvider`（id `deepseek-official`），`dsh-web-search-exa` 导出 `ExaSearchProvider`（id `exa`，**该包未随 dsh 安装**）。均可实例化复用。详见 `docs/knowledge-base/dsh-web-seam.md` 的"各 provider 包的导出与 id"。

## 已核实的关键事实速查

避免重新查文档：

- **`dsh-base` 默认 `fetch: false` 且无 fetch provider** → `web_fetch` 默认不可用，开启它是净新增能力
- **`dsh-base` 已钉 `searchProvider: deepseek-official`** → 不会 AMBIGUOUS，但要接入自己的 provider 必须覆盖 `- id: web` 那一行
- **web seam 无回退链**，多 provider 未配 id 会报 `WEB_PROVIDER_AMBIGUOUS`，不是先到先得
- **`available()` 禁止发网络请求** → 回退只能在调用失败后发生
- **patch 替换整行 config，不合并** → 覆盖时必须写全字段
- **`ctx.web` / `ctx.llm` / `ctx.settings` / `ctx.credentials` 是 seam；`ctx.tools` / `ctx.tokenMeter` 是 core**
- **三个 provider 类都可实例化复用**：`DeepSeekSearchProvider`(id `deepseek-official`)、`ExaSearchProvider`(id `exa`)、`HttpFetchProvider`(id `http`，`available()` 恒真)。**复用时不注册**，否则抛 `WEB_DUPLICATE_PROVIDER`
- **Kenari base URL 分两种形状**：`[OI]` 用 `https://kenari.id/v1`，Anthropic 用 `https://kenari.id`（不带 `/v1`）；形状错误返回 **405 而非 404**
- **Kenari 价格单位是 micro-IDR per 1M tokens**
- **免费模型**：id 加 `:free` 后缀，或 `pricing.free` 为真。`step-3-7-flash:free` 在 Rp 0 账户可用
- **分享页 key 会被拒 balance / usage / quota**（403），spending 工具仍可用
- **计费工具真实扣费**：`web_search`、`web_fetch`、`x_search` 按次计费，失败调用不计费
